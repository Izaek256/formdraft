# Quality strategy

Goal: every requirement has evidence that it works, and every dangerous failure has a test that would catch it. The dangerous failures here are wrong dimensions, silently wrong exports, lost customer files and leaked measurements.

## Principles

1. The SRS acceptance criteria are the contract. Tests exist to prove them (docs/requirements).
2. The expected values for drafting come from people, not from the code (ADR-0013). A pattern maker's hand drafts and the book's worked example are the oracle.
3. Invariants (invariants.md) are tested at the lowest level that can see them, and again through the exporters.
4. A feature is complete only with the evidence in evidence-and-dod.md.
5. Tests are deterministic. No wall-clock time, no unseeded randomness, no network.

## Levels used

| Level | Purpose here | Typical tools (Proposed, confirm in S00) |
|---|---|---|
| UNIT | Rules, validation, unit conversion, geometry functions | cargo test |
| PROP | Round trips, offsets, tessellation, no overlap | proptest with fixed seeds |
| GOLDEN | Output against hand-drafted reference fixtures | cargo test with fixture files and the single tolerance file |
| INTEG | Pipeline across crates, export parsing | cargo test, tools/pattern-cli |
| CONTRACT | Project schema, rulebook, chart data, public interface | cargo test with schema fixtures |
| E2E | Keyboard-only workflow in the app | egui test harness if viable, otherwise recorded manual run |
| SECURITY | No network, no leaks, malformed input | network-disabled run, trace, fuzzing |
| PERF | 150 ms regeneration budget, size budget | criterion benches, CI size script |
| FAULT | Crash during save | fault injection in the sink |
| MIGRATION | Older project files | one fixture per schema version |
| XTARGET | Native versus WASM | same fixtures run on both |
| STATIC | Lints, layering, banned patterns, dependencies | clippy, cargo deny, scripts/ |
| MANUAL | Print, accessibility, pattern maker review | manual-procedures.md |

## Levels not used, and why

| Usual level | Status | Reason |
|---|---|---|
| Database migration tests | Replaced by MIGRATION on project files | No database |
| API contract tests between services | Replaced by CONTRACT on crate interfaces and file formats | No services |
| Authentication and authorization tests | Not applicable | No accounts (ADR-0006) |
| Load and stress tests | Not applicable | Single local user. PERF budgets cover latency |
| Mutation testing | Optional later | Not in the SRS. Consider for pattern_core once stable |

## CI gates (every change)

1. cargo fmt --all -- --check
2. cargo clippy --workspace --all-targets -- -D warnings
3. cargo test --workspace
4. cargo deny check
5. scripts/check-layering.sh
6. scripts/check-no-raw-length-format.sh
7. cargo check -p pattern_core --target wasm32-unknown-unknown
8. The offline test run (from S17)
9. scripts/check-wasm-size.sh on the hosted artifact (from S16)

A red gate blocks merge. A gate may not be disabled to pass a change.

## Rules for tests

- Tolerances live in one data file (set at G0, OQ-17). A test never invents its own tolerance.
- A bug fix starts with a failing test that reproduces it. The test ID is added to the catalog.
- Fixtures are never regenerated by running the code. Changing a fixture needs a human decision and a line in tests/fixtures/CHANGELOG.md.
- A flaky test is a defect. Fix it or remove it with a recorded reason. Do not add retries.
- Test names include the test ID from docs/testing/test-catalog.md.
- Coverage percentage is informational only. Acceptance-criteria coverage and invariant coverage are mandatory.

## Open items that limit testing today

The numeric tolerance for hand-draft agreement (OQ-17), thresholds (OQ-02), the print tolerance (OQ-05) and reference hardware (OQ-23) are undecided. Tests that need them are written against a named tolerance key and fail with a clear message until the value is set. They do not pass on a guessed number.
